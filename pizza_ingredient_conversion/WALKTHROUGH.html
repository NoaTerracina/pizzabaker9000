Pizzabaker9000

Have you ever been in the kitchen and thought “I wish my pizza baking had a little more R in it”?

Me neither!

But I got distracted during a lecture and made a function to convert pizza volume (dL) to mass (g) of various pizza ingredients, so now I’m basing my entire essay and thus also this entire repository around it.

The main appeal is the function that takes a console input value of how many deciliters you would like to convert, requests you choose from a menu of delicious pizza ingredients, and tells you how many grams that volume should correspond to. However, it also spits out a pizza-colored plot of the conversion ratios for the available ingredients.

pizzaplot

This one plots the ingredients’ weight per dL ratios in a size-ordered bar plot with some pretty pizza colors. This function is run here or in the targets pipeline.

Full function with comments:

pizzaplot <- function(df){
  
  # Make nicer labels for the plot
  
  labels <- c(flour = "Flour",
              oil = "Oil",
              water = "Water",
              butter = "Butter",
              dry_yeast = "Dry yeast",
              sugar = "Sugar",
              salt = "Salt",
              pizza_sauce = "Pizza sauce",
              shredded_cheese = "Shredded cheese",
              mozzarella_solid = "Mozzarella blob")
  
  # Choose colors suited for the ingredients
  
  colors <- c(flour = "#E8D5A9",
              oil = "#E8C547",
              water = "#7FB8D6",
              butter = "#F4D35E",
              dry_yeast = "#B08850",
              sugar = "#F5EBDD",
              salt = "#C8C8C8",
              pizza_sauce = "#C0392B",
              shredded_cheese = "#F2A922",
              mozzarella_solid = "#FFF1C9")
  
  # Make a bar chart of the ratios, with pretty colors and labels!
  
  ggplot(df, aes(x = reorder(ingredient, grams.per.dl), # makes the bars size ordered
                 y = grams.per.dl, 
                 fill = ingredient)) +
    geom_col(show.legend = FALSE) +
    scale_x_discrete(labels = labels) +
    scale_fill_manual(values = colors) +
    theme_minimal() +
    labs(x = NULL, y = "g/dL", title = "Ingredient density") +
    theme(axis.text.x = element_text(angle = 45, hjust = 1))
  
}

Try it out:

pizzaplot(conv_rates)

You should now have a beautiful plot of the conversion rates used in the volume to mass conversions!

dl_to_grams

The main attraction of this repository, the big volume to mass conversion function. You run it on your data and it will ask in the console for the volume in dL to convert to grams. After that, it’ll let you choose from a menu of ingredients to convert that volume into dL. The conversion ratios are picked directly from the dataset. Run this function here or in “/converter_function/RUNTHIS_pizza_function.R”.

Full function with comments:

dl_to_grams <- function(df){
  
  # Asking for input volume
  
  repeat { # Continues asking for input until valid input is entered
    
    input <- readline("How many deciliters do you want to convert? Enter here: ")
    
    n_dl <- suppressWarnings(as.numeric(sub(",", ".", input)))  # accepts 2,5 and 2.5
    
    if (!is.na(n_dl) && n_dl > 0) break # Rejects negativity
    cat("Please enter a positive number.\n")
    
  }
  
  # Asking for input ingredient
  
  choice <- menu(choices = c("Flour",
                             "Oil",
                             "Water",
                             "Butter",
                             "Dry yeast",
                             "Sugar",
                             "Salt",
                             "Pizza sauce",
                             "Shredded cheese",
                             "Mozzarella blob"),
                 title = "Choose your ingredient to convert dl to grams of (press 0 to cancel):")
  if (choice == 0) {
    return("Conversion was canceled")  # user cancellation feature
  }
  
  # Example of a choice
  else if(choice == 1){
    return(paste0(n_dl, " deciliters of flour weighs ", # Cutesy output statement
                  n_dl * df$grams.per.dl[df$ingredient == "flour"], "g")) # Uses dataset to access
    # conversion ratio
  }
  
  # Same code new ingredient
  else if(choice == 2){
    return(paste0(n_dl, " deciliters of oil weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "oil"], "g"))
  }
  
  else if(choice == 3){
    return(paste0(n_dl, " deciliters of water weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "water"], "g"))
  }
  
  else if(choice == 4){
    return(paste0(n_dl, " deciliters of butter weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "butter"], "g"))
  }
  
  else if(choice == 5){
    return(paste0(n_dl, " deciliters of dry yeast weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "dry_yeast"], "g"))
  }
  
  else if(choice == 6){
    return(paste0(n_dl, " deciliters of sugar weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "sugar"], "g"))
  }
  
  else if(choice == 7){
    return(paste0(n_dl, " deciliters of salt weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "salt"], "g"))
  }
  
  else if(choice == 8){
    return(paste0(n_dl, " deciliters of pizza sauce weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "pizza_sauce"], "g"))
  }
  
  else if(choice == 9){
    return(paste0(n_dl, " deciliters of shredded cheese weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "shredded_cheese"], "g"))
  }
  
  # Can you tell that I was the one who wrote the else if statements? (very inefficient) 
  else if(choice == 10){
    return(paste0(n_dl, " deciliters of mozzarella blob weighs ", 
                  n_dl * df$grams.per.dl[df$ingredient == "mozzarella_solid"], "g"))
  }
  
  else{
    return("Unknown ingredient!!!") # Rejects nonsensical input
  }
  
}

Targets

What would pizza-baking be without adaptability? (think about it, some cretins put banana on their pizza)

Therefore, this repository has implemented a targets workflow that has stored all functions, data, and the plot, ready for you to load! The best thing about it is that targets will run only your changed files, everything else is already there. So, say you wanna add a new ingredient to the converter (not banana), or would like to edit a ratio, targets takes care of it and implements it straight to the output (just make sure to update functions for new ingredients).

CODE NOT TO BE RUN HERE

_run.R

Let’s walk through it (run separately in “/R/_run.R”) and see what we get! Start with loading targets.

library(targets)

Then run targets.

tar_make()

Now you can load whatever element you like! Here, the plot.

tar_read(plot)

_targets.R

None of the code in this file needs to be run, targets runs this on its own later. However, I like you so much so I’ll walk you through it anyhow. This part loads packages needed for the functions to be run:

tar_option_set(
  packages = c("here", "ggplot2") 
)

This part just instructs targets on what is supposed to run, on what file, and where:

tar_source()

The list has all instructions for what targets should do, let’s go through them step by step:

This one sets the file path to the data

tar_target(
  name = conv_rates_file,
  command = here("data/ingredient_conversion_ratios.csv"),
  format = "file"
)

This one reads the data

tar_target(
  name = conv_rates,
  command = read.csv(file = conv_rates_file)
)

This one runs the plotting function

tar_target(
  name = plot,
  command = pizzaplot(conv_rates)
)

This one would be how the conversion function would be run, but sadly targets isn’t built for interactive code. Run it separately in “/pizza_ingredient_conversion/RUNTHIS_pizza_function.R”

tar_target(
  name = conversion,
  command = dl_to_grams(conv_rates)
)
